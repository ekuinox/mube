# ユニバーサル基板化＋全体カバー 筐体改修 設計書

日付: 2026-08-16

ブランチ: `enclosure/universal-pcb-with-lid`

関連: TASK-4（回路のユニバーサル基板化）、TASK-6（本体上部が重く固定が上から剥がれてくる）

## 目的

1. 電子部品の実装をブレッドボードからユニバーサル基板 P-03229（72×47mm）へ移す。トレイをその基板マウントに作り替える。
2. 配線がむき出しの現状をやめ、プレート上の全部品を覆う一体カバーを新設する。
3. 上記に伴いプレート外形を再設計する。ブレッドボードと Pico を横並びに置く前提が消えるため、大幅に縮められる。

## 背景

- 現行は「オープンベースプレート」構成（PR #79）。プレート（`body.scad`）にペデスタル・ソケット・トレイをボルトオンし、外周壁も蓋も持たない。配線は完全に露出している。
- 現行トレイはハーフサイズのブレッドボード（85.5×54.5）と Pico（51×21）を **横並び** に載せる前提で、これがプレート 115.8×153.1mm という大きさを決めていた。
- TASK-4 で「Pico は基板に直付けせず、Pico 側にオスピンヘッダ・基板側にメスソケットで抜き差しする」ところまで決まっている。Pico が基板の上に重なるので、電子部品エリアのフットプリントは基板 1 枚ぶん（72×47）に縮む。
- P-03229 の既製マウント穴は φ3.2、中心間ピッチ 長辺 66mm × 短辺 41mm（docs/parts-selection.md）。

## 決定事項

ブレインストーミングで確定した内容。

- カバーは **1 部品**。サーボ・ペデスタル・基板・配線のすべてを覆う。
- 屋根は **+Y 方向への単一勾配（45°）**。水平な段は作らない。
- カバーの固定は **M2 × 4 本**。カバー裾の外側に張り出した耳を、プレートのラグへ落とす。ラグの位置は −Y の 2 隅と ±X 壁上の 2 点（四隅ではない。理由は後述）。
- カバー開口は **LED 窓・押しボタンスイッチ・USB 切欠き** の 3 つ。サムターンの手動操作窓は設けない（手動操作はカバーを外して行う）。
- スイッチは基板実装のタクトスイッチをやめ、**パネル取付の押しボタン PS21B-1（秋月 P-04583）をカバーに直付け**する。基板とは 2 本の線で繋ぐ。
- **トレイは残す**。基板を机上で組んでからプレートへ載せられる利点を維持する。カバーとは独立に着脱できる。
- 基板は **横置き**（長辺 72 を X 方向）。縦置きよりプレートの Y 方向が短くなり、重心が低くなる。

## 平面レイアウト

### 基板（P-03229, 72 × 47）

世界座標で X: −27〜45、Y: 35.3〜82.3。中心は (9, 58.8)。

- −Y 端がペデスタル受けカーブ外周（`ped_curb_ro` = 27.7）から `pcb_ped_gap` = **7.6mm** 逃げる。
  この 7.6 は「基板とカーブのすきま」を直接決めた値ではなく、−Y 側のトレイ固定スリーブの
  位置から逆算された結果である。スリーブの中心は `tray_fix_y_lo` = 30.7 で、その上端が
  30.7 + 3.9 = 34.6。基板 −Y 端 35.3 はこれを 0.7 かわす。そしてスリーブ自身がここまで
  +Y に押し上げられているのは、ペデスタルのフランジローブ（45°/135°、先端円の上端 y = 26.21）
  からトレイ床を逃がした結果。つまり支配しているのはペデスタルのローブであって基板ではない。
- 既製マウント穴 4 個は基板ローカルで (±33, ±20.5) ＝ 世界座標 (−24, 38.3) (42, 38.3) (−24, 79.3) (42, 79.3)。

### 基板上の部品配置（基板ローカル座標）

配置は `circuit/parts.ts` のネットリストと Pico W のピン配置から導いた。使用ピンは VBUS / GND / GP14〜GP18 で、**GP14〜GP18 は 5 本とも USB と反対側の端に固まる**（GP14=19 番、GP15=20 番、GP16=21 番、GP17=22 番、GP18=24 番）。VBUS だけが 40 番＝USB 端。

これで Pico の向きが一意に決まる。USB を +X へ向け、1〜20 番列（GP14 / GP15）を **−Y 辺**、21〜40 番列（GP16 / GP17 / GP18 / VBUS）を **+Y 辺** に向ける。結果、LED とスイッチの系統は +Y 側だけで、ゲート駆動とサーボ信号の系統は −Y 側だけで閉じる。

| 部品 | 位置 | 根拠 |
| --- | --- | --- |
| U1 Pico W | 長辺を X に、Y 中央。x −15〜+36 | USB を基板 +X 端に face させる。メスソケット列が y = ±8.89 に来るので既製穴（y = ±20.5）と干渉しない |
| D1 2色LED | (−24, +21) ＝世界 (−15, 79.8) | 屋根の φ6 窓の真下 |
| Rled 330Ω | (−22, +13) | GP16（21 番）直近 |
| Rled2 330Ω | (−28, +13) | GP18（24 番）直近 |
| SW1 用 2pin コネクタ | (−10, +21) ＝世界 (−1, 79.8) | GP17（22 番）直近。スイッチ本体はカバー側 |
| C1 470µF | (+26, +17) ＝世界 (35, 75.8) | V5 ＝ VBUS（40 番、+X 端）直近。サーボの突入を受けるバルクコンなので引き回しを最短にする |
| C2 100nF | (+20, +17) | C1 に隣接（parts-selection.md の指示） |
| Q1 MOSFET | (−27, −17) | GP14（19 番）直近。背が高い（基板上 16mm）が屋根は −Y 側ほど高いので問題ない |
| Rg 220Ω | (−22, −13) | GP14 ⇔ Q1.G の間 |
| Rgs 10kΩ | (−27, −11) | Q1.G ⇔ GND |
| D2 1N5819 | (−8, −19) | SERVO_RTN（Q1.D）とサーボコネクタの間 |
| サーボ 3pin | (+2, −21) ＝世界 (11, 37.8) | 基板の −Y 端。ペデスタルが隣なのでケーブルが最短で降りる。SIG は GP15（20 番、−Y 辺）直近 |

背の高さについては、屋根が +Y へ 45° で降りるので **y が大きいほど置ける部品が低くなる**。
モデル側が持っている予算は 3 段階:

| 予算 | 値 | 置ける範囲 |
| --- | --- | --- |
| `pcb_stack_tall`（TO-220 立て） | 16.0 | 世界 y ≤ `pcb_tall_y_max` = 78.4。基板 +Y 端まで残り 3.9mm の帯には置けない |
| `pcb_stack_mid`（C1 φ8×11.5 / LED φ5×8.6） | 12.0 | 基板上のどこでも可（+Y 端 82.3 でも屋根内面 25.5 に対し 2.1 の余裕） |
| `pcb_stack_low`（抵抗・ダイオード） | 3.0 | 基板上のどこでも可 |

これとは別に、パネル取付スイッチ本体の掃引体が作るキープアウト帯（世界 x −6.8〜4.8、
y 32.5〜59.1、最下点 z 33.18）が独立に存在する。基準が違う（屋根ではなくスイッチ本体との
当たり）ので、`pcb_tall_y_max` だけを見て「この y より内側なら 16mm 級を置ける」と
判断しないこと。

Pico を基板の +X 端まで寄せると (33, 20.5) の既製穴が Pico に近づく。ただし Pico は
基板ローカルで y ±10.5 にしか広がらず、穴は y 20.5 なので **10mm 離れており影には入らない**。
それでも「基板を 4 本のネジで留めてから Pico を挿す」順序は守る（挿した Pico を跨いで
ドライバーを立てるより素直で、ソケットに横力をかけずに済む）。組立手順の 2 を参照。

### トレイ

- 床: X −27.5〜45.5、Y 26.7〜90.9、厚さ 2.4。原点まわりを半径 29 で丸く欠き取り、ペデスタル受けカーブ（半径 27.7、高さ 2.4）をまたぐ。
- 基板支柱 4 本: 世界座標 (−24, 38.3) (42, 38.3) (−24, 79.3) (42, 79.3)、高さ 5、外径 5、下穴 φ2.1（`tray_screw_pilot` と同仕様）。

基板の既製穴は φ3.2 だが、留めるネジは **M2 で統一する**。理由は既存モデルに校正済みの実績があること。`pilot_gauge.scad` と `tray_pilot_gauge.scad` で M2 セルフタップの下穴径を実機で詰めてあり（サーボ耳 2.2、ボス 2.1）、貫通クリアランス 2.4 と頭ザグリ 4.2 も M2 基準で全部品に行き渡っている。BOM のネジも M2×5 の 1 種類だけ。M3 を持ち込むと下穴の校正クーポンを刷り直すところからになる。φ3.2 の穴に M2 を通すとネジ山は効かないが、頭（φ4.2）が基板を支柱へ押さえ付けるので保持には足りる。
- プレート固定スリーブ 4 個: (−22, 30.7) (40, 30.7) (−22, 86.9) (40, 86.9)。既存の `m2_sleeve_solid()` / `m2_sleeve_cuts()` をそのまま流用する。

固定スリーブを基板の ±Y 側に置いたのは、±X 側に置くとプレートの −X 端がドア枠へ寄りすぎるため。−X 側は `clear_left` = 50 の制約があり、カバーの裾と耳を積み上げると余裕がなくなる。±Y 側は制約が緩い。

−Y 側の 2 個（y = 30.7）は、ペデスタルのフランジローブとの干渉ぎりぎりに置かれている。
ローブは (±21.21, 21.21) 中心・半径 5 の先端円を持ち、上端が y = 26.21 まで来る。ここから
トレイ床（`tray_y0` = 30.7 − 3.9 − 0.1 = 26.7）を 0.3 のマージンで逃がすと、スリーブ中心の
下限は 30.513 になる。採用値 30.7 の余裕は 0.187 しかない。スリーブ中心間の距離も
ローブ半幅込みの下限 9.4 に対して 9.519（余裕 0.119）で、この帯の定数はどれも動かすと
assert が鳴る。

### プレート

- 本体外形: X −33.0〜50.8、Y −33.0〜96.2（83.8 × 129.2mm）、角R `cover_round_r` = 2、厚さ 2.4。
  - 各端はカバー裾の外面（−30.7 / 48.5 / 93.9）＋ 外周リブ幅 2 ＋ 嵌合すきま 0.3。リブの内面がカバー裾の外面を 0.3mm のすきまで受ける。
- カバー固定ラグ 4 個: φ`plate_lug_d` = 9 の円を張り出し、外形とフィレットで融合させる。
  中心は `cover_ear_pts` と同一で (−33.5, −33.5) (51.3, −33.5) (−33.5, 86.9) (51.3, 86.9)。
  **四隅ではない**（下記）。
- 中央ロゼット開口・ペデスタル受けカーブ・ペデスタル固定ボス 4 本は現行のまま不変。
- トレイ固定ボス 4 本とカバー固定ボス 4 本は `m2_boss()` を流用（高さ 6、袋下穴でドア面を貫通しない）。
- 上面リブ: 外周のみ、横桟なし。外周リブ（輪郭の内側 2mm、高さ 4）が **カバー裾の位置決めリップを兼ねる**。リブの内面（−30.7 / 48.5 / 93.9）がカバー裾の外面を受け、カバーがリブの内側に落ちる。

STL 実測のバウンディングボックスは **93.8 × 134.2 × 8.4mm**（X −38.0〜55.8、Y −38.0〜96.2）。
−X / −Y の 38.0 はラグが決め、+Y の 96.2 は本体矩形が決める（+Y のラグは角から降りて
y = 86.9 にいるので、+Y 側の最外はラグではない）。ドアクリアランス（`clear_left` = 50、
`clear_down` = 65）に対してそれぞれ 12.0mm / 27.0mm の余裕が残る。

**ラグを四隅に置かない理由。** +Y の 2 個は角ではなく ±X 壁上の y = `tray_fix_y_hi` = 86.9
（トレイ +Y 固定点と同じ y）に降ろしてある。角（y = 96.7）に置くと、カバー側の耳の天面
（z = 12.2）が、耳の +Y リム（96.7 + 3.9 = 100.6）における屋根外面（z = 10.03）を突き抜ける。
カバーは天面をベッドに伏せて刷るので、突き抜けた耳はベッドから 63mm 浮いた孤立島になり、
サポート無しでは刷れない。y = 86.9 なら屋根外面が 23.73（リムでも 19.83）で、耳は壁の
高さにすっぽり収まる。おまけに直線の壁には角丸めの引っ込みが無いため、耳の円が裾の外面へ
1.1mm 食い込んでウェブ無しで裾と一体になる（−Y の 2 隅は角丸めのぶん 0.89mm 浮くので
`cover_ear_webs()` が橋を架けている）。

なおこの判定は必ず耳の **リム** で行うこと。中心（y 96.7）だけを見ると屋根外面は 13.93 で
耳天面 12.2 を上回り、突き抜けが見えない。本改修で 3 度踏んだ「中心をサンプリングして
極値を見落とす」失敗と同じ形である。

**横桟を全廃した理由。** 横桟はプレート全幅に走るので、カバーの −X / +X 側壁の真下を
貫いてしまい、カバーが座らない。よって `plate_rib_ys = []` として全廃し、剛性は M2 で
留められたカバーが肩代わりする。残る外周リブも、カバー固定ボス 4 点の周りを
`max(tray_sleeve_od + 1, plate_lug_d + 0.2)` で丸ごと逃がすため辺を数 mm ずつ食われ、
実体は **閉じた一周ではなく 4 本の独立した直線区間** になる。位置決めリップとしては
X・Y 両方向を直線区間で拘束するので機能上の問題はない。

## カバー

### 外形

footprint は角R `cover_round_r` = 2 の矩形。内面 X −28.7〜46.5、Y −28.7〜91.9。
壁厚 2.0 で外面 X −30.7〜48.5、Y −30.7〜93.9。

屋根は y ≤ `cover_slope_y0` = 34.9 の範囲が水平（外面 z = 75.73 / 内面 z = 72.9）で、
そこから +Y へ 45° で降りる。

```
 z(内面)
 73 ┤   ┌─────────┐
    │   │ サーボ   ╲
    │   │          ╲ 45°
 38 ┤   │           ╲             ← Pico +Y 端(y 69.3)。スタック 23.4 に対し 15.1
    │   │            ╲
 25 ┤   │             ╲___        ← 基板 +Y 端(y 82.3)。C1/LED 23.4 に対し 2.1
 16 ┤   │                 ╲|      ← +Y 端の壁（内面 y 91.9 で z 15.9）
  0 ┴───┴──────────────────┴──→ y
   -28.7 34.9              91.9
```

内面天井の高さは `z = 72.9 − max(0, y − 34.9)`（`roof_in_z()`）。主要な干渉点の余裕。
**各行は部品の中心ではなく、拘束方向（+Y）における部品の極値で評価している**：

| 評価点 | 部品 | 部品上端 | 屋根内面 | 余裕 |
| --- | --- | --- | --- | --- |
| y ≤ 34.9（平天井域） | サーボ本体上端 | 70.9 | 72.9 | 2.0 |
| y 78.4（`pcb_tall_y_max`） | MOSFET (TO-220 立て) | 27.4 | 29.4 | 2.0 |
| y 69.3（Pico の +Y 端） | Pico / USB コネクタ | 23.4 | 38.5 | 15.1 |
| y 82.3（基板の +Y 端） | C1 / LED（`pcb_stack_mid`） | 23.4 | 25.5 | 2.1 |
| y 90.8（スリーブの +Y リム） | トレイ +Y 固定スリーブ天面 | 12.2 | 17.0 | 4.8 |
| y 90.9（トレイ床 +Y 端） | トレイ床上面 | 4.8 | 16.9 | 12.1 |

このうち **y 82.3 の行が `cover_slope_y0` を支配している**。他の屋根 assert と揃えた +2 の
マージンを要求すると下限が 34.8 になり、この定数の慣習どおり 0.1 を足して 34.9 を手置き
している。評価点を C1 の実座標ではなく基板の +Y 端に取っているのは、基板上の部品配置が
モデル化されておらず（はんだ実装は TASK-4 でこれからやる作業）、配置が動いても assert を
書き換えずに済ませたいため。「12mm 以下の部品なら基板のどこに置いてもよい」という
不変条件として読む。

スイッチ本体は屋根ではなく基板と当たるので上表とは別枠。φ11.5 の円柱を法線方向に 26mm
掃引した最下点が z 33.18 で、Pico スタックの上端 20.9 に対して 12.28 の余裕がある。

### 開口

| 開口 | 位置 | 寸法 |

LED 窓は φ6 なので +Y リムが y 82.8 まで来て、基板の +Y 端 82.3 を 0.5mm はみ出す。屋根に

**スイッチ（PS21B-1 / 秋月 P-04583）**

パネル取付のモーメンタリー押しボタン（OFF-(ON)、A 接点）。カバーの斜面に開けた穴へ外から差し込み、内側からナットで締める。基板とは 2 本の線で繋ぐ。

| 項目 | 値 |
| --- | --- |
| キャップ | φ14 × 高さ 7.6（パネル面より外） |
| フランジ | φ18.7 × 厚さ 3.5 |
| ネジ部の長さ | 8.3（ナットを除き挟めるパネル厚は約 5.8） |
| パネル面より内側の奥行き | 26（旧ロット図 37.0 − 7.6 − 3.5。2017 年図の 22.4 より厳しい方を採用） |
| ネジ部の外径 | φ11.5（実測 2026-08-16。旧ロット図の 11.50 と一致）。取付穴は印刷公差を見て φ12.0 |

取付位置を LED と同じ y ではなく **y 55** としたのは、本体の奥行き 26mm を逃がすため。
取付点の屋根外面は z = 55.63。斜面の法線方向 (0, −0.707, −0.707) に 26mm 伸ばすと軸上の
先端は世界 (−1, 36.6, 37.24) に来る。

当たり判定に使うのは軸上の先端ではなく、φ11.5 の円柱として掃引した立体の **最下点**
(−1, 40.7, **33.18**) である。掃引体は世界 x −6.8〜4.8 / y 32.5〜59.1 の帯を通る。この帯の
真下にある最も背の高いスタックは Pico（上端 20.9）で、余裕は 12.28mm。ここに
`pcb_stack_tall` 級（上端 27.4）の部品を置いてはいけない。

斜面に付くが、**実効パネル厚は 2.0mm**（= `cover_wall`）である。スイッチの軸は斜面の法線
方向を向いており、ネジ部が通る材料は斜めに切られないため。以前この項は 2.0 ÷ cos45° ＝
2.83mm と書いていたが、それは「斜面を垂直方向に貫いた場合」の厚みで、この取付には
当てはまらない。いずれにせよネジ部 8.3mm に対して十分収まる（旧値は真の厚みより大きく、
比較の向きとしては保守側だったので、誤って通していたわけではない）。

座面の **φ19 のザグりは実装していない**。屋根は勾配域では単一の平面であり、座面の範囲
（y 45.5〜64.5）は全域がその平面上にあるので、ザグらなくても最初から平らである。
フランジ φ18.7 はそのまま座る。

**カバーと基板の切り離し**: スイッチがカバー側に付くため、カバーは 2 本の線で基板に繋がれる。線の端を 2pin のピンヘッダ／ソケットにして抜き差しできるようにする。ピンヘッダは既に BOM にあるので部品追加はゼロ。カバーを外したら線を抜いて完全に分離できる。

**LED の見え方**

LED（φ5、本体高さ 8.6）は窓の真下に座り、**窓越しに真上から覗く**構図になる。頭を窓まで
持ち上げることは幾何的にできない。以前この項は「足を約 7.2mm 伸ばせば頭が穴の位置まで
上がる」と書いていたが、これは誤りである。

LED は垂直な φ5 の円柱で、その上を 45° の屋根が横切っている。したがって先に屋根へ当たるのは
頭の中心ではなく **+Y 側のリム**（y = 82.3）で、そこの屋根内面は z = 25.5。基板上面 11.4 と
本体高さ 8.6 を引くと、足を伸ばせる幾何上限は

```
25.5 − 11.4 − 8.6 = 5.5mm   （リムが屋根に接触する限界）
```

`pcb_stack_mid` = 12.0 の予算内に収めるなら 12.0 − 8.6 = **3.4mm** まで。

この上限まで伸ばしても頭は窓に入らない。窓の内口（斜面の穴が内面と交わる円）は、法線方向に
`cover_wall` = 2.0 進んだ位置にある半径 3 の円で、中心は (−15, 78.39, 29.41)、内面の平面は
`y + z = 107.8`。x = −15 の断面で内口は y 76.3〜80.5 に開いている。一方 LED のリムが屋根に
触れる点は y = 82.3 で、これは内口の +Y 端より **1.8mm も +Y 側**、つまり穴ではなく肉のある
屋根である。最大まで伸ばした状態でも頭の上面は内面から穴の軸方向に約 1.8mm 下（足を
伸ばさなければ約 5.7mm 下）に留まる。

真上から鉛直に覗いたときに見通せる開口は、外口と内口それぞれの鉛直投影（どちらも x 方向
半径 3・y 方向半径 2.12 の楕円で、中心が y 方向に 1.41 ずれている）が重なるレンズ形で、
おおよそ x −18〜−12、y 77.7〜80.5 に収まる。LED の頭（中心 (−15, 79.8)、φ5 なので
y 77.3〜82.3）はこれと十分に重なる。よって **真上からの視認性は確保されている**。斜めからの視認性を上げたい場合は、足を曲げて頭を穴の方向（+Y かつ上）
へ傾ければよい。モデル側はどの実装でも成立するので、実装時の任意とする。

### 固定

裾の外面から張り出す耳 4 個。耳の実体は `m2_sleeve_solid()` / `m2_sleeve_cuts()` をそのまま流用する（ボス逃げボア＋自己サポートファンネル＋頭ザグリ、トレイとペデスタルで実機検証済みの構造）。中心はプレートのラグ中心と一致させる。

配置は **−Y の 2 隅 ＋ ±X 壁上の 2 点（y = 86.9）**。四隅ではない。理由は「プレート」の項に
書いたとおり、+Y の角に置くと耳がその位置の屋根を突き抜けて伏せ印刷で孤立島になるため。
−Y の 2 隅は角丸め（`cover_round_r` = 2）のぶん耳の円が裾から 0.89mm 浮くので、
`cover_ear_webs()` が「最寄りの角の丸め円 ⇔ 耳の円」の凸包だけで橋を架ける。裾の外形全体と
凸包を取ると耳から遠い辺まで接線で結ばれて側壁の外にヒレが生えるので、対象は角ごとに絞る。
この橋が無いとカバーの STL は連結成分が 5 個に割れる（`components.ts` が検出する）。

裾はプレート上面（z = 2.4）に着地し、外面が外周リブ（高さ 4）の内面に受けられて XY 位置決めされる。ネジは抜け止め専任。

印刷部品は プレート / ペデスタル / ソケット / トレイ / カバー の 5 点。現行から カバー 1 点だけ増える。

## 組立手順

順序に依存する箇所があるので明記する。

1. 基板へ部品をはんだ実装する（Pico はまだ挿さない）。
2. 基板をトレイの支柱 4 本へ M2 で留める。Pico を挿す前に済ませること。
3. Pico をメスソケットへ挿す。
4. ペデスタルをプレートへ M2×4 で留め、サーボを天板へ M2×2 で留める。
5. トレイをプレートへ M2×4 で留める。サーボのケーブルを基板の 3pin へ接続する。
6. スイッチ PS21B-1 をカバーの斜面の穴へ外から差し込み、内側からナットで締める。
7. スイッチの 2 本の線を基板の 2pin ソケットへ挿す。
8. カバーを被せ、4 個のラグへ M2×4 で留める。

分解は逆順。カバーの 4 本を抜き、2pin を抜けば殻が完全に分離する。

## 印刷方向

- カバー: **天面をベッドに伏せる**。屋根が第 1 層になるためブリッジが発生せず、45° の勾配面も自己サポートで刷れる。サポート不要。
- プレート / トレイ / ペデスタル / ソケット: 現行と同じ向きで変更なし。

屋根に水平な段（二段屋根）を作れないのは、低い側の屋根が第 1 層より下に宙で現れて垂れるため。単一勾配にしているのはこの制約による。

## 重量とバランス（TASK-6 への影響）

**すべて STL の実測値**（メッシュの符号付き四面体体積の総和）。密度は中身の詰まった PLA
1.24 g/cm³ とした。実際のプリントはインフィルで軽くなるが、比較の比率は変わらない。
「現行」は本ブランチの分岐元 `ab95b98` のモデルを同じ方法で測ったもの。

| 部品 | 現行 | 改修後 |
| --- | --- | --- |
| プレート | 45.89 cm³ / **56.9g** | 27.44 cm³ / **34.0g** |
| トレイ | 30.01 cm³ / **37.2g** | 12.08 cm³ / **15.0g** |
| カバー | — | 69.08 cm³ / **85.7g** |
| 計 | 75.90 cm³ / 94.1g | 108.60 cm³ / 134.7g |
| 差引 | | **+32.70 cm³ / +40.6g** |

ペデスタル（23.52 cm³ / 29.2g）とソケット（19.39 cm³ / 24.0g）は本改修で変わらない。

以前この表は概算で「プレート 53g → 30g、トレイ 30g → 15g、カバー 70g、差引 +32g」と
書いていた。実測すると現行側も改修後側もそれぞれ重く、**正味の増加は +32g ではなく +41g**
だった。TASK-6 は「上部が重くて上から剥がれる」問題なので、この数字を甘く見積もっては
いけない。

平天井（全高 75.73mm 一定）のカバーを実際にビルドして測ると 85.04 cm³ / 105.5g で、
45° 勾配にすることで **19.8g** 削れている（当初の概算「約 24g」に近い）。

`cover_slope_y0` を 31.2 から 34.9 へ上げた Ruling 12 のコストは 67.62 → 69.08 cm³、
すなわち **+1.8g**。全高（`cover_top_z`）は変わらず、平天面が +Y へ 3.7mm 伸びて斜面が
そのぶん短くなり、+Y 壁が 3.7mm 高くなるだけなので、材積の増減はほぼ相殺する。

プレートが 117.8×153.1 から 93.8×134.2（ラグ込みの実測バウンディングボックス）に縮むことで
重心はドア面側・軸側に寄る。しかし **面ファスナーの接着面積も同じ比率で減る** うえ、
上に 85.7g のカバーが乗って上部が重くなる方向に働く。TASK-6（上から剥がれる）が改善すると
は断言できない。むしろ正味 +41g のうちの大半が高い位置に付くので、悪化する可能性の方を
先に疑うべきである。実機で確認し、駄目なら面ファスナーの配置・種類で対応する。
**この設計では解決しない**、というのが正直なところ。

削除する BB 系 assert の代わりに置く。

- 基板が受けカーブに干渉しない: `pcb_ped_gap >= 1`（`pcb_off_y` の定義に代入すると
  この形に縮退するので、そのまま直に書く）
- 基板の支柱がトレイ床に収まる／支柱とトレイ固定スリーブが融合しない
- トレイ固定スリーブが 基板 / 受けカーブ / ペデスタルのフランジローブ のいずれとも干渉しない
- カバー内面が トレイ / 基板 の外形を包含する（-X / -Y 側だけが実効。+X / +Y 側は
  `cover_x1` / `cover_y1` が `tray_x1` / `tray_y1` から導出されており恒真になる）
- 屋根内面の高さが各部品の上端を上回る（上表の各行。**部品の中心ではなく +Y の極値で評価する**）
- +Y の耳の天面が屋根を突き抜けない（伏せ印刷で孤立島にならない。耳のリムで評価する）
- カバー固定ラグを含めたプレート最外がドアクリアランス内: `<= clear_left`, `<= clear_down`
- LED の位置が基板の X / Y 範囲内
- 屋根に開ける法線穴が斜面の範囲内（`roof_normal_hole()` の中でガードする）
- スイッチの実効パネル厚（`cover_wall`）が `sw_thread_l` 未満
- スイッチ本体の掃引体の**最下点**が Pico スタックに当たらない
- スイッチの座面 φ`sw_seat_d` が斜面に収まる

書かない assert の方針も決めてある。同じ定義式から導いた値どうしの比較（例: `tray_x0` <=
基板 −X 端。`tray_x0` の定義がまさにそれ −0.5）は恒真でガードとして働かないので置かない。
また、ある assert が別の assert に完全に包含される場合も重複させない（低背部品版は
中背部品版に包含される）。

### 段取り 8 を撤回した理由

tscircuit の ERC が検証するのは **導通だけ** である。フットプリントやシンボルのパッド数を
差し替えても、この検証が見る情報は 1 ビットも変わらない。したがって SW1 を「基板実装の
タクト」から「2pin コネクタ」へ描き替える作業には、検証上の利得がまったく無い。

よって `circuit/` 側のネットリスト表現は **意図的に据え置く**。SW1 のシンボルは 4 パッドの
押しボタンのままで、`netlist.tsx` の `ALLOW_UNCONNECTED` が `SW1.pin3` / `SW1.pin4` を
未接続として許容し続ける。

物理的な実態は「SW1 は基板外のパネル取付部品（PS21B-1）であり、基板とは 2 本の線＝2pin
コネクタで繋がる」であって、これは筐体側（`cover.scad` のスイッチ穴）と BOM
（`docs/parts-selection.md`）が表現している。`circuit/` の役割は結線の正しさの検証なので、
そこに物理実装の形を持ち込む必要はない。

この意図は `circuit/netlist.tsx` の `ALLOW_UNCONNECTED` のコメントに記録してある。
表示用のラベル（`circuit/breadboard/footprints.ts` の SW1 の `value`）だけは実物に合わせて
`"Tact"` → `"PS21B-1"` に直した。こちらは配線図を読む人間向けの表示であって、
ERC の入力ではない。
