# ユニバーサル基板の配線設計とピン再割当

日付: 2026-08-23
関連: TASK-4（回路のユニバーサル基板化）、#90 `06c325c`（筐体側の基板化とカバー新設）

## この文書が決めること

1. GPIO の再割当。実装位置と割当の食い違いを解消する。
2. 基板上の部品配置。#90 の設計書からの差分として書く。
3. 配線見本を生成するツール `circuit/perfboard/` の構成。
4. 方位の書き方と、その取り違えを機械的に検出する仕組み。
5. #90 の設計書のうち、ピン列の向きに関する記述の訂正。

はんだ実装そのものと実機確認は TASK-4 に残る。

## 方位

軸の向きの正は `enclosure/models/params.scad` にある。
原点はサムターン軸（ロゼット中心）で、`clear_left = 50 // -X to door edge/frame` と `clear_down = 65 // -Y to door handle` の 2 行が −X と −Y の意味を固定している。
レバーハンドルはサムターンの下にあるので、−Y は下である。

視点は **室内側からドアを正面に見て** に固定する。
この錠は室内側のサムターンに付くので、屋外側から見た向きで書くと左右が反転する。

| 軸 | 向き | 根拠 |
| --- | --- | --- |
| +X | 右 | `clear_left` が −X をドア枠側と定めている |
| −X | 左（ドア枠側） | 同上 |
| +Y | 上 | `clear_down` が −Y をレバーハンドル側と定めている |
| −Y | 下（ハンドル側） | 同上 |
| +Z | 手前（室内へ突き出す） | ペデスタルとサーボが立つ向き |
| −Z | 奥（ドア面へ） | 同上 |

**書き方の規則**：本文と表で軸に触れるときは `+X（右）` の形で毎回併記する。
両側をまとめて指すときは `±X（左右）` と書く。
座標の組（`(0, +16.5)` など）と、`x −17.8〜+30.5` のような範囲には併記しない。数が続く場所に括弧を挟むと読めなくなるためである。

**取り違えの防止**：併記は同じ情報を何度も書き写す操作なので、更新のたびに反転する余地がある。
実際、本書の草稿を書く過程で「+Y は手前」と誤って述べた箇所があった。
そこで対応表を `scripts/axes.ts` に 1 つだけ置き、`scripts/axes.test.ts` が次の 3 点を検査する。

- `docs/**/*.md` と `enclosure/models/*.scad` に現れる併記の括弧の中身が、対応表と一致すること
- 併記を含む文書が「室内側から」という視点の宣言を一度は含むこと
- `params.scad` の `clear_left` と `clear_down` のコメントが −X と −Y の意味を保っていること

3 点目は、対応表の根拠が消えたときに失敗させるためのものである。
筐体の向きを変える改修が入れば、この検査が落ちて対応表の見直しを促す。

`circuit/perfboard/render.ts` は同じ対応表から方位の凡例を SVG に描く。
はんだ付けのときに見るのは図なので、図と文書が同じ定数を見ている状態にする。

検査には限界がある。
「右側の壁」のように軸記号を伴わない散文は照合できない。
方向を述べるときは併記記法を使う、という規約とセットでのみ効く。

## 前提の訂正

#90 の設計書は、基板上の部品配置をこう導いている。

> これで Pico の向きが一意に決まる。USB を +X へ向け、1〜20 番列（GP14 / GP15）を **−Y 辺**、21〜40 番列（GP16 / GP17 / GP18 / VBUS）を **+Y 辺** に向ける。

この二つは同時に成り立たない。
Pico W のピン列は、USB を −X（左）に向けたときに 1〜20 番列が −Y（下）側へ来る。
基板を横置きに保ったまま回せる向きは 0 度と 180 度の二つしかないので、USB を +X（右）に向ければ 1〜20 番列は必ず +Y（上）側になる。

実装中の基板は正しい向きで組まれている。
+Y（上）側に D1 と SW1 用の 2pin コネクタが載り、−Y（下）側にサーボコネクタ、Q1、C1、C2 が載る。
C1 が VBUS（40 番）の直近という条件を満たす位置にあることが、−Y（下）側が 21〜40 番列だという読みを裏づける。

よって #90 が決めた幾何は訂正を要しない。
USB は +X（右）を向き、カバーの切欠きは +X（右）の壁にあり、背の高い部品は屋根の高い −Y（下）側に載る。
直すのは設計書の列の対応と、その記述に引きずられた C1 と C2 の座標である。

| 箇所 | 現在の記述 | 訂正 |
| --- | --- | --- |
| 「基板上の部品配置」導入文 | 1〜20 番列を −Y 辺、21〜40 番列を +Y 辺 | 1〜20 番列が +Y（上）辺、21〜40 番列が −Y（下）辺 |
| C1 470µF | (+26, +17) | −Y（下）側へ移す |
| C2 100nF | (+20, +17) | −Y（下）側へ移す |
| 各行の「根拠」欄のピン番号 | GP14〜GP18 を前提 | 本書の割当に合わせて書き換え |

## 座標系

以降は基板ローカル座標（原点は基板中心、x −36〜+36、y −23.5〜+23.5）と、穴グリッドの列行の両方で書く。

**列**：+X（右）端を 1 列目として −X（左）方向へ数える。基板に印刷された番号と一致する。
**行**：−Y（下）端を A として +Y（上）方向へ数える。

25 列 16 行を仮定すると、列 c の x は `30.48 − 2.54 × (c − 1)`、行 r の y は `2.54 × (r − 8.5)` になる（行 A を r = 1 とする）。
この仮定の根拠と、外れたときに何が動くかは決定 3 に書く。

Pico はソケットの pin1 を 1 列目に置き、+X（右）端いっぱいまで寄せる。
このとき pin n（1〜20 番）は列 n に、pin n（21〜40 番）は列 41 − n に来る。
ピン列は行 E（y = −8.89、21〜40 番）と行 L（y = +8.89、1〜20 番）である。

## 決定 1: GPIO の再割当

**割当の原則**：部品の足と同じ列、または隣の列にヘッダピンが来るように選ぶ。
すずめっき線が Pico を跨がないことを、配線の短さより優先する。

| ネット | 現行 | 変更後 | 物理ピン | 列 | 位置の根拠 |
| --- | --- | --- | --- | --- | --- |
| LED_DRV_R | GP16 | GP9 | 12 番 | 12 | D1 の R 足と同じ列 |
| LED_DRV_G | GP18 | GP10 | 14 番 | 14 | D1 の G 足と同じ列 |
| BTN | GP17 | GP5 | 7 番 | 7 | 2pin コネクタの信号足と同じ列 |
| SERVO_SIG | GP15 | GP22 | 29 番 | 12 | サーボ 3pin コネクタと同じ列 |
| GATE_DRV | GP14 | GP20 | 26 番 | 15 | Q1 と同じ列 |

D1 はコモンカソードで、K は 13 番（列 13、GND）へ真下に 1 本で落ちる。
SW1 のコネクタは、もう一方の足が 8 番（列 8、GND）へ真下に落ちる。
どちらも GND ピンが足の列にそのまま来るので、GND 網を引き回さずに済む。
−Y（下）側では 28 番（列 13、GND）が Q1 の 2 列隣に来るので、Rgs の落とし先もその場にある。

ファームで機械的な変更が要るのは PWM だけである。
RP2040 は GPIO 番号 n に対して slice が `(n >> 1) & 7`、channel が `n & 1` で決まる。
現行の GP15 が slice7 の ch B であるのはこの規則によるもので、GP22 は slice3 の ch A になる。
`Pwm::new_output_a(p.PWM_SLICE3, p.PIN_22, PwmConfig::default())` へ差し替える。

LED は押し引き出力、ボタンは内部プルアップと立ち下がりエッジ待ちで、いずれも RP2040 の全 GPIO で同じ動作をする。
`mube-core` のロジックはピン番号を知らないので、host テストの期待値は変わらない。

この割当は 21、22、24、25 番（GP16、GP17、GP18、GP19）を −X（左）端の連続した空き帯として残す。
TASK-3 の磁気センサはここに入る。
基板の −X（左）側に空き地ができること（決定 2 の末尾）と合わせて、センサ用のコネクタを置く場所と、そこへ届くピンが同じ側にそろう。
ADC が要る方式を選んだ場合に備えて、31、32、34 番（GP26、GP27、GP28）も空いたままにする。

## 決定 2: 部品配置

#90 の表からの差分だけを挙げる。
列の値は部品の中心が乗る列で、足が複数列にまたがる部品は範囲で書く。

| 部品 | #90 | 本書（列, 行） | ローカル座標 | 変更の理由 |
| --- | --- | --- | --- | --- |
| D1 2色LED | (−24, +21) | 12〜14, O | (0, +16.5) | 3 本足が 12、13、14 番ピンの列に乗る |
| Rled 330Ω | (−22, +13) | 12, M〜N | (+2.5, +12.7) | GP9 と D1.R の間 |
| Rled2 330Ω | (−28, +13) | 14, M〜N | (−2.5, +12.7) | GP10 と D1.G の間 |
| SW1 用 2pin | (−10, +21) | 7〜8, N | (+14, +14.0) | 足が 7、8 番ピンの列に乗る |
| C1 470µF | (+26, +17) | 4〜5, B〜C | (+22, −15.2) | −Y（下）側へ。VBUS（列 1）と GND（列 3）に近く、サーボへの 5V の引き回しの途中に入る |
| C2 100nF | (+20, +17) | 3, B | (+25.4, −16.5) | C1 に隣接（parts-selection.md の指示） |
| Q1 MOSFET | (−27, −17) | 15, B〜C | (−5.1, −15.2) | GP20 の真下。サーボコネクタの隣で、SERVO_RTN のループが最小になる |
| Rg 220Ω | (−22, −13) | 15〜16, D | (−6, −11.4) | GP20 と Q1.G の間 |
| Rgs 10kΩ | (−27, −11) | 14, C〜D | (−2.5, −12.7) | Q1.G と 28 番 GND の間 |
| D2 1N5819 | (−8, −19) | 13〜14, B | (+1.3, −16.5) | Q1.D とサーボコネクタの間。列 12 は SERVO_SIG が通るので空ける |
| サーボ 3pin | (+2, −21) | 11〜13, A | (+2.5, −19.1) | ペデスタル直上。SIG が GP22 と同じ列に来る |
| U1 Pico W | x −15〜+36 | 1〜20, E と L | x −17.8〜+30.5 | 穴グリッドの端で決まる。決定 3 を参照 |

基板の上半分（+Y、上）が表示と入力、下半分（−Y、下）が動力と電源になる。
背の高い部品が下に集まるのは、屋根が +Y（上）へ 45 度で降りるためである。

高さの予算は #90 の表がそのまま効く。
Q1 は世界座標 (3.9, 43.6) で、TO-220 立てが許される `pcb_tall_y_max` = 78.4 に対して十分内側にある。
D1 は世界座標 (9, 75.3) で、`pcb_stack_mid` = 12.0 の予算内であり、屋根のメッシュに覆われない 3 帯（−Y（下）端側 y 35.3〜39.01、−X（左）端側 x −27〜−21.70、+X（右）端側 x 39.50〜45）のいずれからも離れている。

サーボコネクタは #90 の (+2, −21) から行 A の (+2.5, −19.1) へ 1.9mm だけ +Y（上）へ動く。
穴が y = −21 に無いためで、ペデスタルまでのケーブルの取り回しには影響しない。

配置の副作用として、基板の −X（左）側におよそ 18 × 40mm の空き地ができる。
Pico が +X（右）端へ寄り、部品が Pico の直近へ集まった結果である。

## 決定 3: 穴グリッド

配線見本は穴の識別子で結線を指示するので、グリッドの寸法を確定させる必要がある。
写真から列が 25 本であることは読めるが、行数は読めていない。

グリッドが満たすべき条件は二つある。
ソケットの 2 列は 7 ピッチ離れる。
#90 が Pico をピン列 y = ±8.89 に置いているので、グリッドの中心から等距離の位置に穴が要る。
後者は行数が偶数のときに限り成り立つ。
行数が奇数なら Pico は中心から 1.27mm ずれた位置に載り、#90 の y = ±8.89 という記述もそのぶんずれる。

本書は 25 列 16 行（行 A から行 P）を仮定する。
16 行なら行 E と行 L がちょうど y = ∓8.89 に来て、#90 の記述と一致する。
実測で行数が違っていたら `circuit/perfboard/board.ts` の定数 1 つを直す。
決定 1 の割当は部品の足とピンの列の関係だけで決まっているので、行数が変わっても割当は変わらない。動くのは決定 2 の y 座標だけである。

列数が 25 でなかった場合は、決定 1 まで影響する。
ピンの x はソケットが刺さる列で決まり、部品はその列に合わせて置くからである。
25 列という読み取りが外れていたら、サーボコネクタが乗る列（ペデスタル直上、x ≈ +2）に来るピンを取り直し、そのピンを SERVO_SIG に割り当て直す。

Pico の x 位置も、#90 が書いている「x −15〜+36（+X（右）端に face）」のままにはならない。
穴グリッドは基板の端まで届かないので、ソケットが刺さる最も +X（右）寄りの列で決まる。
25 列が基板中心に対して対称なら 1 列目は x = +30.48 で、Pico の +X（右）端は約 +31.9 になる。
#90 の想定より 4mm ほど内側なので、カバーの USB 切欠き（+X（右）の壁、中心 (47.5, 58.8, 22.15)）から USB コネクタまでの距離がそのぶん伸びる。
プラグが届くかは実機で確認する。ここは本書では決めない。

## 決定 4: 配線見本ツール

`circuit/breadboard/` を一般化せず、`circuit/perfboard/` を別に作る。
ブレッドボードは列タイで穴が最初から繋がっているのに対し、P-03229 は片面めっきでランドが独立しているので、導通のモデルが根本的に異なる。
`breadboard/` の `place.ts` と `route.ts` は自動配置と自動配線のためのもので、配置を人が決める本書の方針では使わない。
共有するのは `model.ts` の `UnionFind` と、SVG 描画の下回りだけにとどめる。

| モジュール | 役割 |
| --- | --- |
| `board.ts` | 穴グリッドのモデル。`Hole = {col, row}`、穴の識別子（`L12` など）、ローカル mm への変換。導通は一切持たない |
| `layout.ts` | 人が書く配置データ。部品の足から穴への対応表、ソケット 40 ピンから穴への対応、ワイヤの一覧（`{from, to, net, side}`） |
| `verify.ts` | `parts.ts` の `NETS` と `layout.ts` を突き合わせる検証 |
| `render.ts` | SVG と結線表の生成。方位の凡例は `scripts/axes.ts` から描く |

正は `circuit/parts.ts` の `NETS` のままである。
`layout.ts` は「どの穴に何を置いたか」だけを持ち、繋がっているかどうかを主張しない。
主張を検証するのは `verify.ts` の仕事であり、この分担なら配置を動かしても嘘が入り込まない。

`verify.ts` が見るのは次の 5 点である。

- `NETS` の各ネットについて、全端点が同一の union-find グループに属すること
- 異なるネットが同一グループに属さないこと（ショートの検出）
- `NETS` の全端点が穴に割り当てられていること（配線の取りこぼしの検出）
- 同じ穴に 2 本以上の足が入っていないこと
- `netlist.tsx` の `ALLOW_UNCONNECTED` に挙がるピンは未接続でよいこと

ソケットの 40 ピンのうち、`NETS` に現れないピンは穴を占有するだけで配線を持たない。
これは検証の対象外とし、同じ穴に足が入っていないかだけを見る。

配線は片面めっき基板なので裏面のすずめっき線が基本になる。
ワイヤは `side: "solder" | "component"` を持ち、表を這わせる線も表現できるようにしておく。
描画は部品面から見た図とし、裏を通る線は破線で描く。

出力は 2 つ。
`circuit/build/perfboard.svg` は派生物なのでコミットしない。
結線表の markdown は穴の識別子で from と to を並べたもので、これはコミットする。

テストは `bun test circuit/` に載るので `just erc` でそのまま回る。
